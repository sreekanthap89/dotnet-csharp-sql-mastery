	234	All steps
	235	Resolve the name.The browser asks DNS for api.contoso.com. A CNAME points at the Front Door endpoint.
	236	DNS answers.DNS returns an anycast IP, so the request will land on the nearest edge location. The answer is cached for its TTL.
	237	Reach the edge.The request arrives at the nearest edge PoP. Static files would be served from cache right here; this API call is dynamic, so it continues.
	238	Front Door: TLS, WAF, routing.Front Door terminates TLS, runs WAF rules and routes to the healthiest, closest regional backend.
	239	API gateway.API Management validates the JWT, applies the per-client rate limit and forwards to the right backend version.
	240	ASP.NET Core pipeline.Kestrel hands the request to the middleware pipeline: exception handling, authentication, authorization, then the endpoint.
	241	Check the cache.Cache-aside: the API looks up order:42 in Redis first. This time it is a miss.
	242	Query the database.On a miss the API queries SQL Server: the slowest hop in the chain, which is why we cache.
	243	Populate the cache.The row comes back and the API stores it in Redis with a TTL, so the next read is a hit.
	244	Response travels back.JSON returns through APIM, Front Door and the edge to the browser. Total ≈ 80 ms; a cache hit next time skips SQL entirely.
